しくみ

メニューバーに常駐して、棚をいつも整えておきます。

1. 放置中のプロジェクトを見つける

各プロジェクト自身のファイルを読んで技術スタックを判断し、作り直せるビルド成果物の量を測ります。最近触れたプロジェクトはそのままにします。

2. 片付ける

ワンクリックで片付けるか、空き容量が目標を下回るたびに自動モードに任せます。最も長く放置されているプロジェクトから順に片付けます。

3. 起こす

古いプロジェクトをもう一度開くと、Mothball が気づきます。「起こす」を選ぶと、そのスタックに合った復元手順を実行します： npm install, flutter pub get, pod install.

これらはすべて、安心して片付けられます。

ここにあるフォルダは、どれもコマンドひとつで作り直せます。Mothball がそれを片付けるのは、まわりのプロジェクトからその正体が確かめられたときだけです。

安全を前提に設計

動かしたままにしておけるほど慎重です。

使うのが怖いクリーナーは、結局使われません。Mothball は推測するくらいなら、そのフォルダを見送ります。

  • git が追跡しているものには一切触れません。 コミットされているものは、あなたのものです。
  • フォルダ名だけで判断しません。 build という名前のフォルダも、まわりのプロジェクトがそう示しているときだけビルド成果物とみなします。
  • コミットされていない作業があれば、使用中とみなします。 作業中の変更があるプロジェクトはスキップします。
  • 移動する直前にもう一度確認します。 スキャンのあとで何か変わっていれば、手を引きます。
  • 削除せず、ゴミ箱へ。 すべての移動は記録され、.mothballignore で残したいものを指定できます。

ターミナル派ですか？

すべての機能を CLI でも使えます。

同じエンジン、同じ安全チェックを、macOS、Windows、Linux で。

$ mothball scan ~/dev

$ brew trust herocodess/tap
$ brew install --cask mothball
